## 設計上の重要な決定（案）

| # | 決定 | 区分 | 理由（要約） |
|---|---|---|---|
| D1 | エージェントは**グラ補助ツール（Python）に組み込む** | 推奨・要判断 | チャットアプリ連携・音声合成・再生・DB・テストの土台がすでにある。ひといき（Electron）はAI APIはあるがチャット連携が無い |
| D2 | 新しい処理は `files/agent/` の**別モジュール**に置き、`auto_reply_app.py` は画面と既存機能の受け口に留める | 推奨 | 12,400行の1ファイルにこれ以上混ぜない。画面（tkinter）に依存しない形にしてテストしやすくする |
| D3 | 依存の向きは **既存 → エージェント**（既存側がチャットの出来事を渡し、エージェントは既存コードを import しない） | 推奨 | 循環 import を避け、エージェントを単体でテストできる |
| D4 | 並行処理は**スレッドと待ち行列**（今の作りと同じ）。asyncio は入れない | 推奨 | 既存の22か所のスレッドと揃える。混在させると停止・後片付けが複雑になる |
| D5 | **発言の判断と文章の生成を分ける**（判断は構造化出力で「沈黙」を明示的に返す） | 指示どおり | 沈黙のときに生成・音声合成・再生を一切しない |
| D6 | 判断の前に**規則による関所**（重複・自分の発言・頻度上限・処理中・費用上限）を置き、AIを呼ばずに沈黙できる | 推奨 | 費用と遅延を抑え、暴走を規則で止められる |
| D7 | AI API は**提供元に依存しない共通インターフェース**＋提供元ごとのアダプター。共通化できない機能は「能力フラグ」と拡張口で扱う | 指示どおり | 提供元が未確定 |
| D8 | **APIキーは Windows の DPAPI で暗号化して保存**（平文で保存しない・ログに出さない・URLに入れない） | 推奨 | 今の設定は平文の key-value。ひといきも DPAPI を使っている |
| D9 | 音声合成は**AivisSpeech を第一候補**、VOICEVOX を代替。両者は同じ呼び出し方のアダプター1つで扱う。VOICEPEAK は連携方式を検証してから | 本人の希望＋事実 | 既存コードで AivisSpeech と VOICEVOX は同じ HTTP の手順で動いている |
| D10 | **音声合成と再生を分け、再生を途中で止められる**ようにする | 推奨 | 今の再生は止める手段が無い（音の長さだけ待つ作り） |
| D11 | AIがツールを**提案**することと**実行**することを分け、実行は登録・権限・入力・回数を検証してから | 指示どおり | 任意のコマンド実行をさせない |
| D12 | エージェントのデータは**別の SQLite ファイル** `agent_data.db` に置く | 推奨・要判断 | 既存の `app_data.db` の表を変えずに済み、消す・バックアップするのも別にできる |
| D13 | AIの声を**音声ルームに流すこと（他の人に聞こえる）は、別のスイッチで明示的にONにしたときだけ** | 推奨 | 人に届く操作は、本人の了解をとってから、という今までの方針と揃える |
| D14 | **他の人の声を聞く**（2026-10-15 追加要望）: 話し始めたら聞く側（LISTENING）に回り、話し終わったら文字起こしをチャットの出来事と同じ流れで判断する。AI は話している人に割り込まない | 本人の希望 | 「音を拾う」「文字起こし」の方式は要検証・要判断 |
| D15 | **人物モデル**（2026-10-15 追加要望: 声の記憶・人物像の推定・関係性の値）は、最初は**画面の席の表示で誰が話したかを決め**、声紋は使わない。推定は「仮説」として扱い、口に出さない。繊細な事柄は推定させない。機能ごとに本人がONにし、人ごとに見る・直す・消すができる | 推奨 | 他の人の個人情報（声紋は法令上も慎重に扱う情報）。06 の 8章 |
| D16 | **チャットで会話する**（2026-10-15 追加要望）: 出力先を「声」「チャット」「両方」から選ぶ。チャットへの送信は**既存の手入力送信の経路（監視ワーカー）だけ**を通し、入力欄(`etText`)・読み戻しの確認・自分の発言の除外をそのまま使う。既定は「承認して送る」 | 推奨 | 送信を別スレッドから行うと画面を取り違える事故が起きた（既存の決まり）。人に届く操作は本人の了解をとる |

## 本人に決めてほしいこと（主なもの）

詳しくは各設計書の「未確定事項」。影響の大きいものだけ挙げる。

1. **エージェントを置く場所**（D1）: グラ補助ツールに組み込む／ひといきを広げる／新しいアプリ
2. **AI API の提供元とモデル**: 決まるまでは模擬（モック）で作り、APIキーの欄は提供元を選べる形にする
3. **AIの声を音声ルームに流すか**（D13）: 流す場合の守り（内容の確認、緊急停止、頻度）
4. **他の人の発言をどこまで保存するか**（期間・長期記憶に残してよい情報）
5. **費用の上限**（1日・1か月）と、超えたときの動き
6. GRAVITY の利用規約で、自動化（読み取り・自動発言・音声の取り込み）がどう扱われるか【未確認】
7. **声を聞く方式**: ルームの音の拾い方（要検証）、文字起こしをPCの中でするか外部のAPIに送るか（費用・精度・他の人の声を外へ出すか）
8. **人物モデルをどこまで使うか**: 人物像の推定・関係性の値を使うか、声紋を使うか（最初は使わない案）
