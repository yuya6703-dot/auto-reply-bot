# 08 テスト・運用設計書

## 1. テスト方針

| 方針 | 内容 |
|---|---|
| 置き場所 | `tests/`（既存の方針。消える場所に置かない） |
| 外部依存は模擬に | AI API・音声合成・再生・音を拾う・文字起こし・チャットの出来事・時計を、模擬に差し替えて動かす（各アダプターに `mock.py`） |
| 本物の画面を使う | チャットの出来事は、伏せ字にした実物の画面（`tests/fixtures/`）から作る |
| 実際の API・実機を使うテスト | `--live` を付けたときだけ動く（既存の `test_live_newline.py` と同じ。費用がかかるので本人の了解をとって流す） |
| 既存のテスト | 全部が通り続けること（各段階の完了条件） |
| 時間 | 時計を差し替えて、待ち時間（区切り・頻度上限）を一瞬で進める |
| 判断の質 | AI の判断が「場面に合っているか」は、模擬では確かめられない。**場面集（シナリオ）を作り、実際の API で流して点数を付ける**仕組みを段階4で作る【要判断: 費用】 |

## 2. テスト項目

形式: 目的 / 前提 / 操作 / 期待。テストのファイル名は案。

## 3. ログ

### 3.1 何を残すか

| 出来事 | 置き場所 | 中身（伏せ字を通す） |
|---|---|---|
| 起動・終了・状態の変化 | 画面のログ＋`logs` 表（既存） | 状態の名前、理由 |
| 出来事の受け取り | `events` 表 | 07 |
| 判断の結果 | `decisions` 表＋画面のログ（短く: 「🤫 沈黙（頻度上限）」「💬 反応」） | 行動・理由・規則の番号 |
| AI API の呼び出し | `usage_records` 表＋画面のログ（失敗だけ） | 提供元・モデル・目的・トークン数・費用の見積もり・所要時間・失敗の種類。**送った文・返った文の全文は残さない**【要判断: 調べもの用に一定期間だけ残すか】 |
| ツール | `tool_runs` 表 | 06 |
| 音声合成と再生 | `utterances` 表＋画面のログ | 文・声・成功/失敗/取り消し |
| エラー・時間切れ | 画面のログ＋`error_log.txt`（既存の `write_error_log`） | 伏せ字を通した例外 |

### 3.2 伏せ字

1. APIキーらしい文字列を伏せる（新規）
2. 第三者の名前を伏せる（既存の `mask_screen_text`。`logs` 表に入れるとき）
3. エージェントの表（`events` など）は判断に名前が要るので伏せないが、保存期間で消す（07）

### 3.3 保存期間

| 置き場所 | 期間 |
|---|---|
| `logs` 表 | 既存（最大5,000行） |
| `error_log.txt` | 既存（期間なし）【改善の候補: 大きさの上限】 |
| エージェントの表 | 07 の表のとおり |

## 4. 障害対応

| 障害 | 自動の動き | 本人がすること |
|---|---|---|
| AI API が落ちている・使いすぎ | DEGRADED（AI を呼ばず記録のみ）。60秒ごとに確認して自動で戻る | 待つ。続くなら提供元の状況を確かめる |
| APIキーが無効 | DEGRADED。画面に表示 | 設定でキーを入れ直す |
| 音声合成エンジンが落ちている | 自動起動（設定がONなら）。だめなら発言を捨てて知らせる | エンジンを起動する |
| 出力デバイスが無い | 既定のデバイスで鳴らす（既存） | 出力先を選び直す |
| 音を拾えない | 音声の検知を止めて知らせる（チャットだけで動く） | 入力デバイスを確かめる |
| チャットが読めない（部品の変更） | 出来事が来ないだけ（エージェントは待つ） | 監視側の対応（既存） |
| 費用の上限に達した | AI を呼ばない。画面に表示 | 上限を上げるか、翌日・翌月を待つ |

## 5. 停止と復旧

| 操作 | 場所 | 動き |
|---|---|---|
| AIを開始/停止 | AIタブ | 3.3 の `start`/`stop` |
| 音声を止める | AIタブ・メインタブ（既存の読み上げにも効く） | 再生を即座に止め、待ち行列を空に |
| 緊急停止 | AIタブ（常に見える位置）。キーボードの近道【要判断】 | AI・音声・ツール・聞き取りをすべて止める。手で再開するまで何もしない |
| 異常終了の後 | 起動時 | エージェントは**止まった状態で起動**する（勝手に喋り始めない）。DB の整合性を確かめる。途中だったツールは「中断」として記録 |

## 6. API 利用量と費用の管理

| 項目 | 内容 |
|---|---|
| 記録 | AI を呼ぶたびに `usage_records` に、提供元・モデル・目的（判断/生成/要約/確認）・トークン数を残す |
| 費用の見積もり | 設定の値段の表（100万トークンあたりの入力/出力/キャッシュ）× トークン数。**見積もり**であり請求額ではないと画面に書く |
| 上限 | 1日と1か月の上限（円またはドル）【要判断: 金額】。8割で画面に知らせ、10割で AI を呼ばない |
| 表示 | AIタブに「今日 ◯円 / 今月 ◯円（見積もり）」と、目的ごとの内訳 |
| 下げる工夫 | 規則の関所で AI を呼ばずに済ませる、判断と生成を分けて沈黙時は生成しない、変わらない部分を先頭に置く（キャッシュが効く提供元）、送る会話の上限 |
