# 05 AI API・音声合成・再生・文字起こし アダプター設計書

## 1. 方針

- 共通インターフェースで**できることの最大公約数**を決め、提供元ごとの差は**能力フラグ**と**拡張口（extras）**で扱う
- 共通化できないものを無理に共通化しない（使えないときは「使えない」と返す）
- 提供元の SDK・依存は、そのアダプターのファイルの中だけで import する（入っていなくても他は動く）

## 2. AI API アダプター

### 2.1 共通インターフェース

```python
# llm/base.py
@dataclass
class LLMMessage:
    role: Literal["user", "assistant"]
    content: str                          # 今は文字だけ（画像・音声は扱わない）

@dataclass
class ToolDef:
    tool_id: str
    description: str
    input_schema: dict                    # JSON Schema

@dataclass
class LLMRequest:
    purpose: Literal["decide", "generate", "summarize", "ping"]  # 費用の集計とモデルの選び分けに使う
    system: str
    messages: list[LLMMessage]
    response_schema: dict | None = None   # 構造化出力（JSON Schema）
    tools: list[ToolDef] = ()
    max_output_tokens: int = 1024
    timeout_seconds: float = 20.0
    extras: dict = field(default_factory=dict)   # 提供元固有の指定（下の 2.3）

@dataclass
class LLMUsage:
    input_tokens: int | None
    output_tokens: int | None
    cached_input_tokens: int | None
    raw: dict                             # 提供元が返した利用量そのまま（伏せ字にしてから保存）

@dataclass
class LLMResponse:
    text: str | None
    structured: dict | None               # response_schema に合わせて解釈したもの
    tool_calls: list[ToolCall]            # 提案されたツールの利用（実行はしない）
    stop: Literal["end", "max_tokens", "tool_use", "refusal", "other"]
    usage: LLMUsage
    provider: str
    model: str
    latency_ms: int

class LLMProvider(Protocol):
    name: str
    capabilities: LLMCapabilities         # structured_output / tool_calls / prompt_cache / streaming / usage
    def complete(self, request: LLMRequest, cancel: CancelToken) -> LLMResponse: ...
    def ping(self, timeout_seconds: float = 10.0) -> PingResult: ...   # 接続確認（費用の小さい方法で）

class LLMError(Exception):           # 共通の失敗の種類
    kind: Literal["timeout", "rate_limited", "server", "auth", "bad_request",
                  "refused", "schema_mismatch", "network", "cancelled"]
    retryable: bool
    retry_after: float | None
```

### 2.2 何が共通化できるか

| 機能 | 共通化 | 説明 |
|---|---|---|
| メッセージの送受信 | **できる** | system＋user/assistant の並び。提供元ごとの形への変換はアダプターの仕事 |
| 会話コンテキストの受け渡し | **できる** | 毎回まとめて送る（提供元の会話の保存機能は使わない。送る量を自分で決めるため） |
| 構造化出力 | **条件付き** | 対応している提供元は JSON Schema で縛る。対応していない・失敗したら「JSON で返して」と指示して自分で検証し、合わなければ1回だけ作り直し |
| ツール呼び出し | **条件付き** | 提案を `ToolCall(tool_id, arguments)` の形に揃える。対応していなければ、構造化出力の `tool` 欄で代える（04 の判断の型がそれ） |
| 時間制限・取り消し | **できる（自分で持つ）** | 時間制限は各 SDK・HTTP に渡す。取り消しは「結果を捨てる」で揃える（通信の途中で止められるかは提供元・方式による） |
| 失敗と再試行 | **できる** | `LLMError.kind` に揃える。再試行は**この層で1回まで**。SDK の自動再試行は切るか回数を合わせ、二重にしない |
| 利用量・費用 | **一部** | 入出力のトークン数は揃えられる。値段は提供元・モデルごとに設定（自動で取れないので手で入れる） |
| 提供元固有の機能 | **できない（拡張口で）** | プロンプトの使い回し（キャッシュ）・考える深さの指定・安全上の拒否の扱い など → `extras` と能力フラグ |

### 2.4 提供元の追加の手順

1. `llm/<提供元>.py` に `LLMProvider` を実装（変換・失敗の種類の対応表・能力フラグ・`ping`）
2. 依存を `requirements.txt` に版を固定して足し、spec の hiddenimports を確かめる
3. 値段の表（入出力 100万トークンあたり）を設定に足す
4. 模擬の応答（録った応答を伏せ字にしたもの）で単体テストを書く。実際の API を使うテストは `--live` のときだけ
5. 設定画面の「提供元」の選択肢に足す

## 3. AI API キーの入力と保存（本人の要望。段階1で作る）

本人の要望: 「AI API という値を入力して保存するための箱と、保存するための機能と、そのボタン」。

### 3.1 画面

設定タブに区画「🤖 AI API」を足す（既存の区画と同じ作り。`build_ai_api_section`）。

```
🤖 AI API
  提供元:  [ Claude ▼ ]              ← 選ぶとその提供元のキーの状態を表示
  APIキー: [ ●●●●●●●●●●●●●●●● ] [👁] [💾 保存] [🗑 削除] [🔌 接続確認]
  状態:    保存済み（暗号化してこのPCに保存）／未保存
  ※ キーはこのPCのWindowsユーザーだけが復元できる形で暗号化して保存します。
     ログや画面には表示しません。
```

| 部品 | 動き |
|---|---|
| 提供元 | 選択肢は実装済みのアダプターだけ（最初は「模擬」＋決まった提供元） |
| APIキーの欄 | `show="●"`。右クリックで貼り付けできる（既存の `_show_entry_context_menu`）。保存したら欄を空にする |
| 👁 | 押している間だけ文字を見せる（押し続けない限り隠す） |
| 💾 保存 | 前後の空白・改行を除き、形を確かめて（空でない・長すぎない・改行を含まない）暗号化して保存。ログには「保存しました」だけ |
| 🗑 削除 | 確認して、保存済みのキーを消す |
| 🔌 接続確認 | 別スレッドで `ping`（時間制限10秒）。結果は「つながりました」「キーが違うようです」「つながりません」だけ。キーや応答の中身は表示しない |
| 状態 | 「保存済み」「未保存」「環境変数から読み込み中」のどれか。**キーの一部（末尾4文字など）も表示しない** |

### 3.2 保存のしかた【推奨】

| 項目 | 内容 |
|---|---|
| 暗号化 | Windows の DPAPI（`CryptProtectData`・`CryptUnprotectData`）を標準の `ctypes` で呼ぶ。現在の Windows ユーザーだけが復元できる。**新しい依存は要らない** |
| 保存先 | 既存の `settings` 表に、キー名 `ai_api_key.<提供元>`、値 `dpapi:v1:<base64>`（暗号文だけ） |
| 読み出し | 使う直前に復元し、使い終わったら変数を持ち続けない。復元できない（別のユーザー・別のPC）ときは「未保存」として扱い、再入力を求める |
| 環境変数 | 提供元の標準の環境変数（例: Claude は `ANTHROPIC_API_KEY`【事実: スキルの資料】）があれば、それを優先して読む（保存はしない） |
| 渡し方 | SDK の引数かヘッダーで渡す。**URL・クエリに入れない**（エラーログに URL が残るため） |
| ログ | キーらしい文字列（提供元の接頭辞・長い英数字）を伏せる処理を `mask_screen_text` の前に通す。例外の文言も伏せてから `error_log.txt` へ |
| バックアップ | 自動更新のバックアップ（アプリフォルダの zip）には `app_data.db` が入るが、中身は暗号文だけ |

**代わりの方式**

| 方式 | 良い点 | 弱い点 |
|---|---|---|
| DPAPI（推奨） | 依存なし。ひといきと同じ考え方 | Windows 専用（このアプリは Windows 専用なので問題ない） |
| Windows 資格情報マネージャー（`keyring` など） | OS の画面からも見える・消せる | 新しい依存が要る |
| `cryptography` で自前の鍵 | 依存はすでにある | 鍵をどこに置くかの問題が残る（採らない） |

### 3.3 テスト

| テスト | 期待 |
|---|---|
| 保存→読み出し | 同じキーが戻る。DB には `dpapi:v1:` で始まる暗号文だけがある |
| 平文が残らない | DB ファイル・ログ・画面のログに、キーの文字列が1回も出てこない |
| 削除 | 読み出すと「未保存」 |
| 壊れた暗号文 | 例外で止まらず「未保存」になる |
| 形の確認 | 空・改行入り・長すぎるキーは保存しない |
| 接続確認 | 模擬の提供元で、成功・認証エラー・時間切れの3通りの表示 |
| 画面 | 欄が「●」で隠れている。保存後に欄が空になる。👁 を離すと隠れる |

## 4. 音声合成アダプター

### 4.1 共通インターフェース

```python
# speech/tts_base.py
@dataclass
class VoiceRef:
    engine: str            # "aivisspeech" / "voicevox" / "voicepeak"
    speaker_id: str        # エンジン内の話者（スタイル）の ID
    label: str             # 表示名（キャラ名・スタイル名）

@dataclass
class SynthesisParams:
    speed: float = 1.0
    pitch: float = 0.0
    intonation: float = 1.0
    volume: float = 1.0
    extras: dict = field(default_factory=dict)

@dataclass
class AudioClip:
    wav: bytes             # 16bit PCM の WAV（既存の再生がこれを前提にしている）
    duration_seconds: float

class TTSEngine(Protocol):
    name: str
    capabilities: TTSCapabilities      # styles / params / health_check / auto_start
    def health(self, timeout: float = 2.0) -> bool
    def list_voices(self) -> list[VoiceRef]
    def synthesize(self, text: str, voice: VoiceRef, params: SynthesisParams,
                   cancel: CancelToken) -> AudioClip
```

### 4.2 AivisSpeech（第一候補）・VOICEVOX

【事実: 既存コード】両者は同じ手順で合成できている。そこで**1つのクラスを宛先違いで2つ使う**（`VoicevoxCompatibleEngine`）。

| 項目 | AivisSpeech | VOICEVOX |
|---|---|---|
| 宛先（既定） | `http://127.0.0.1:10101` | `http://127.0.0.1:50021` |
| 話者の一覧 | `GET /speakers`（キャラ → スタイル → ID）。入れた音声モデルで変わる。既定の話者IDは持たない（既存の方針） | 同じ。既定の話者あり（ずんだもん） |
| 合成 | `POST /audio_query?text=&speaker=` → `POST /synthesis?speaker=`（WAV） | 同じ |
| 起動の確認・自動起動 | 既存（`/version`、起動待ち 90秒） | 既存 |
| 調整（速さ・高さ・抑揚・音量） | `audio_query` の値を書き換える【要検証: AivisSpeech での効き方。VOICEVOX と意味が違う項目があるか】 | `audio_query` の値を書き換える【要検証: 既存コードでは書き換えていない】 |

**既存の動きを保つ**: 話者の保存形式「エンジン名:ID」、合成結果のキャッシュ（40件）、エンジンの自動起動、アクセント解析（スマホ）。

**感情とスタイル**（AivisSpeech を活かす）

AI の文の `emotion`（04）を、話者のスタイルに対応づける。対応は人格の `VoiceProfile` に持つ。

```python
@dataclass
class VoiceProfile:
    default: VoiceRef                       # 例: AivisSpeech の「〇〇 / ノーマル」
    by_emotion: dict[str, VoiceRef]         # 例: {"joy": 〇〇/喜び, "sad": 〇〇/悲しみ, "calm": 〇〇/ノーマル}
    params: SynthesisParams
```

- スタイルの名前（喜び・悲しみ など）は音声モデル次第なので、**自動で決めず、設定画面で本人が対応づける**（一覧は `/speakers` から）
- 対応が無い感情は `default` で喋る

### 4.3 VOICEPEAK【未確認】

- このPCには見つからなかった。連携の方式（コマンドライン・ほか）、利用条件（ライセンスで自動化・配信がどう扱われるか）、対応機能（感情の調整など）を**入手して調べてから**アダプターを作る
- 共通インターフェースは、`TTSEngine` を満たせば足せる形にしておく（HTTP でない方式でも、`synthesize` が WAV を返せばよい）

### 4.4 失敗時

| 失敗 | 動き |
|---|---|
| エンジンが応答しない | 設定で自動起動がONなら起動を試す（既存）。だめならその発言は捨て、画面に知らせる（既存の文） |
| 話者が無い（モデルを外した） | 既定の話者に戻さず、喋らずに知らせる（違う声で喋らない） |
| 代わりのエンジンへ切り替えるか | 既定は**しない**（声が急に変わるのは人格として不自然）。設定で許可したときだけ |

## 6. 文字起こし・音声入力アダプター（2026-10-15 追加）

```python
class AudioCapture(Protocol):

class VoiceActivityDetector(Protocol):
```

| 部品 | 最初の案 | 状態 |
|---|---|---|

**守り**: 生の録音は保存しない（文字起こしが終わったら捨てる）。外部の文字起こしに送る場合は設定で明示的に許可したときだけ。
