# リリース手順（自動ビルド＆自動リリース）

`.github/workflows/release.yml` を設定済みなら、以下の3手順だけで新バージョンを配布できます。
手元でのexeビルドやGitHub Releaseページの手作業は不要です。

## 手順

1. **コード内のバージョンを上げる**

   `auto_reply_app.py` の冒頭にある以下の行を、新しいバージョン番号に書き換える。

   ```python
   APP_VERSION = "1.1.0"
   ```

2. **変更をコミットしてpush**

   ```bash
   git add auto_reply_app.py
   git commit -m "v1.1.0: 変更内容の説明"
   git push
   ```

3. **バージョンと同じ番号でタグを作り、push**

   ```bash
   git tag v1.1.0
   git push origin v1.1.0
   ```

   ※ タグ名の数字部分（`v1.1.0` の `1.1.0`）は、手順1の `APP_VERSION` と必ず一致させてください。
   ずれるとアプリ側のアップデート判定がおかしくなります。

## 何が自動で起きるか

タグをpushすると、GitHub Actions が自動的に：

1. Windows環境でPythonと依存パッケージをセットアップ
2. PyInstallerで `自動送信ボット.spec` を使い、`dist/自動送信ボット` フォルダ一式をビルド
   （`--onedir` 方式、exe＋依存ファイル）
3. そのフォルダの中身を `auto_reply_app.zip` にまとめる
4. zipを添付した新しいGitHub Releaseを、タグ名と同じバージョンで自動作成
5. リリースノートも、前回タグからのコミット履歴をもとに自動生成

### ⚠️ exe名について（重要）

アプリの自動更新は、**今動いているexeと同じ名前のexe** をzipの中から探して差し替えます。
そのため、ビルドされるexe名が配布中のexe名（`自動送信ボット.exe`）と食い違うと、
更新が必ず「zip内に見つかりません」で失敗します。

これを防ぐため、CIは手元と同じ `自動送信ボット.spec` を使ってビルドしています。
exe名を変えたい場合は、specファイルの `name=` を書き換えてください
（`.github/workflows/release.yml` 側にexe名を直接書かないこと）。

⚠️ exe名を変更した場合、**変更後のバージョンから先** でないと自動更新は成功しません。
配布済みの旧バージョンは古い名前のexeを探し続けるためです。
名前を変える場合は、利用者に手動での入れ替えを案内してください。

### 画面に出る名前とexe名が違うこと

2026-10-15、画面に出るアプリの名前を「**グラ補助ツール**」に変えた（窓の題・デスクトップのショートカット）。
**exe名は `自動送信ボット.exe` のまま**にしてある。上の理由で、変えると配布済みの版が自動更新できなくなるため（本人と決定）。
画面の名前は `auto_reply_app.py` の `APP_DISPLAY_NAME` だけで決まる。exe名（specの `name=`）と揃える必要は無い。

進捗は、GitHubリポジトリの「Actions」タブから確認できます（数分かかります）。
完了すると「Releases」ページに新しいzipが並び、アプリ内の「🔄 アップデート確認」ボタンや
起動時の自動チェックで検知されるようになります。

## アップデート適用時の動作（アプリ内）

- 新しいzipをダウンロードし、一時フォルダに展開
- 展開したフォルダの中から新しいexeを探し、そのフォルダを新しいアプリ本体として使用
- 更新前に、現在のアプリフォルダ一式を `%USERPROFILE%\AutoReplyTool_Backups` にzipでバックアップ
- `app_data.db`（キーワード設定・各種設定）と `error_log.txt` は上書き・削除の対象外（ユーザーデータは保持されます）
- アプリを終了し、外部PowerShellスクリプト(.ps1)がファイルの差し替えを行う
  （フォルダ名に日本語が含まれるとcmdのbatでは誤動作するため、PowerShellを使っています）

## ログのコピー

メインタブのログは読み取り専用ですが、コピーできます。動作の報告や不具合の相談に使ってください。

- **「📋 ログをコピー」ボタン** — ログ全体を一発でコピー
- **右クリック** — コピー / すべて選択 / ログ全体をコピー / 表示を消去
- **Ctrl+A** で全選択（TkのTextは既定でCtrl+Aが「行頭へ移動」なので割り当て直しています）
- マウスでドラッグして一部だけ選び、右クリック→コピーも可能

⚠️ クリップボードの自動読み上げがONでも、ここでコピーした内容は読み上げられません
（自分でコピーしたものは監視対象から外しています）。

「表示を消去」で消えるのは**画面の表示だけ**です。監視ログのDB保存分は消えません。

## エミュレータ(MuMu)の検出・起動

設定タブの「📱 エミュレータ(MuMu)」で、MuMu本体と監視対象アプリの起動をツールから行えます。

- **接続先(adbのホスト/ポート)はMuMuに直接問い合わせます。** 手で設定する必要はありません
- 「🔄 一覧を取得」でMuMuにインストール済みのアプリが並ぶので、監視したいアプリを選びます
  （パッケージ名を手入力する必要はありません。自動化補助のATXは一覧から除外されます）
- 「監視を開始するとき、MuMuと上のアプリを自動で起動する」をONにすると、
  MuMuが落ちていても起動→Android起動完了を待つ→対象アプリを開く、まで自動で行います
- 「▶ 今すぐ起動」「🔌 接続を確認」でその場で試せます

⚠️ **adbのポートを決め打ちしてはいけません。** MuMu Player 12はインスタンスごとにポートが変わり、
ホストも `127.0.0.1` とは限りません（実測環境では `192.168.1.7:5555` で、
以前試していた `127.0.0.1:7555` / `16384` はどちらも接続拒否でした）。
`MuMuManager.exe info -v <番号>` が正確な値を返すので、必ずそちらを使ってください。

⚠️ **インスタンス番号も決め打ちしてはいけません。** MuMuをアップデートすると番号が変わります
（実測: 5.30 では `0`、6.4.7 では `1`）。しかも端末が1台しか無くても `is_main` が `false` に
なるため、「0番」も「メイン」も当てになりません。`info -v all` の一覧から拾ってください。
本ツールは番号を自動検出し、保存済みの番号が実在しない場合は自動で読み替えます
（優先順: 起動中 > メイン指定 > 一番小さい番号）。

MuMuManagerがエラーを返した場合（`{"errcode": -200, "errmsg": "player index not found"}` など）は、
その `errmsg` をログに出します。「MuMuが起動しない」ときはまずログを確認してください。

MuMuが入っていない環境（BlueStacks / LDPlayer など）では、この機能は自動的に無効になり、
従来どおりadbの探索で接続します。

## AI API のキー（設定タブ「🤖 AI API」）

AIの機能（AIチャット・音声エージェント。設計は リポジトリ直下の `設計書/`）で使うAPIキーを保存します。

- **提供元**: 今は「未定（あとで提供元を決める）」と「テスト用（模擬）」だけです（2026-10-15 時点で提供元は未定）。
  「未定」でも、手元のキーを今のうちに保存しておけます
- **APIキーの欄**は「●」で隠れます。「👁」を**押している間だけ**中身が見えます
- **💾 保存**: キーを確かめて（空・空白や改行入り・日本語・長すぎるものは不可）、暗号化して保存します。保存したら欄は空になります
- **🗑 削除**: 確認してから、保存済みのキーを消します
- **🔌 接続確認**: 提供元が決まるまでは「テスト用（模擬）」でだけ試せます（通信しません）。
  入力欄にキーがあればそれを、無ければ保存済みのキーを使います
- **状態**: 「保存済み」「未保存」「読み出せない（別のWindowsユーザー・別のPCで保存したもの）」のどれかを表示します。
  キーの一部（末尾など）も表示しません

⚠️ **キーの守り方**: Windows の DPAPI で暗号化し、`app_data.db` の `settings` 表に暗号文だけを保存します
（キー名 `ai_api_key.<提供元>`、値 `dpapi:v1:…`）。暗号化したWindowsユーザーでしか読み出せません。
キーは画面のログ・DBのログ・`error_log.txt` に出しません（キーらしい文字列は「＊＊＊(秘密)」に伏せます）。
提供元の標準の環境変数が設定されていれば、保存したキーよりそちらを優先します（環境変数のキーは保存しません）。

## AIタブ（試す段階）

会話に加わるAIです。AIは「テスト用（模擬）」か **Gemini（Google）** を使えます。
手で入れた出来事のほかに、**「💬 GRAVITYのチャットをAIに渡す」をONにすると、監視中に読んだチャット欄の新しい行**もAIに届きます。

1. 設定タブ「🤖 AI API」で提供元を選ぶ（Gemini なら APIキーも保存する。キーは Google AI Studio で作れます）
2. AIタブの「▶ 開始」
3. 「📥 出来事を入れて試す」に名前と本文を入れて「📥 入れる」（Enter でも可）
4. 「🧾 判断のログ」に、黙ったか（🤫）・保留したか（⏸）・喋ったか（💬 🗣️）と、その理由が出ます

- **模擬AIの返事**: 「台本」は、本文に「？」があれば参加、「笑・w・草」があれば短く反応、ほかは沈黙します。
  「いつも沈黙」「いつも参加」などに切り替えて、流れを確かめられます
- **続けて入れると、まとめて1回だけ判断します**（最後の出来事から2.5秒静かになったら）。AIの名前を呼ぶと待たずに判断します
- **喋った後8秒は、自分から話しません**（名前を呼ばれたときは別）。1分に2回・1時間に30回までしか喋りません
- **AIの呼ばれ方**: 「、」で区切って複数書けます（あだ名と、メンションで使うアカウント名など）。どれかを含む出来事には、
  待たずに・喋った直後でも反応します。最初に書いたものが、AIが自分を名乗る名前です。
  チャット欄で「@名前..」と切れて出たメンションも、先頭が呼ばれ方か自分のアカウント名と同じなら「呼ばれた」とみなします
- 呼ばれたのに回数の上限（チャットは1分に1通）に当たったときは、捨てずに上限が空くまで待ってから返事します
- **オーナーの名前**: あなたのGRAVITYでの表示名。AIはこの人と親しく話します（規則や守ることは変わりません）
- AIには、今の日時と、ルームの様子（ルーム名・人数・座っている席の数・アナウンス）も渡します（画面を読むだけで、押しません）。
  発言に「あなた宛て」「ほかの人宛て」の目印を付けるので、ほかの人どうしの話には割り込みにくくなります
- **💭 静かなときに自分から話しかける**（既定OFF）: 直近30分にやりとりがあった場で、5分誰も書かないと、話題を出すかを考えます
  （話さないと決めることもあります。15分に1回まで）
- チャットに書くときは、改行を2つまで使い、声より長く書けます（短い反応60字・参加200字まで）
- **@ メンション**（最初からON。AIタブ「⚙️ 設定」）: 特定の人にチャットで返すときは、文の頭に「@アカウント名 」を付けます。
  AIが「たろうさん」のような呼び方で相手を決めても、チャット欄に出ているアカウント名に当てはめます（当てはまらなければ付けません）
- **😊 チャットで気持ちを絵文字で表す**（最初からON）: AIが気持ちに合う絵文字を1〜2個まで選びます（真面目な話では控えめに）
- **💬 話しかけられたら続けて話す**（最初からON）: 呼ばれたとき・返事をした相手（そのあと90秒）には、ふだんの上限
  （チャットは1分に1通）を越えて、1分に4回まで続けて返します（チャットは連投に見えないよう3秒はあけます）。
  返事をした相手とは、名前を呼ばれなくても会話が続きます
- **反応しない人**（AIタブ「⚙️ 設定」）: 名前を入れた人の発言には反応しません（荒らし対策）。その人のことは覚えません（会話の記録には残ります）
- **オーナーの合図**: オーナー（「⚙️ 設定」のオーナーの名前）がチャットでAIに呼びかけて、
  「静かにして（10分・1時間 など。書かなければ30分）」「もういいよ」「〇〇って覚えておいて」と言えます。
  静かな間はAIタブに表示され、「🔈 静かにを解く」でPCからも戻せます
  - ⚠️ オーナーは名前でしか見分けられないので、同じ名前にすれば誰でも合図できてしまいます。
    そのため「覚えて」は「（オーナーから）」と付けたふつうの記憶にして、記憶の一覧で見て消せるようにしています
- **🔎 頼まれたら調べる**（既定OFF）: チャットで「〇〇って何？調べて」「明日の横浜の天気は？」などと頼まれたら、
  Wikipedia（日本語版）か天気（Open-Meteo）を調べて答えます。調べる前に「ちょっと調べるね、待ってて！」とチャットに出します
  - 「待っての一言」はAIタブで変えられます（空にすると出しません）。下書きを見せる設定でも、この一言だけは確かめずに送ります
  - 調べるのは1時間に10回まで。調べる言葉（作品名・地名など）が Wikipedia・Open-Meteo へ送られます
  - 答えには「Wikipediaによると」などと出典を添えます。最新のニュースなどは調べられません

### 👂 声を聞く（AIタブ。最初はOFF）

- ルームの音をPCの音声入力に入れると（iPadをPCのライン入力・USBの音声入力につなぐ、仮想ケーブル など）、
  話し声を文字にしてAIに渡します。AIは「声（だれか）」の発言として判断します（誰が話したかは分かりません）
- 「音声入力」で入力を選び、「今の音量」を見ながら、声だけが「しきい値」を超えるように合わせてください
- 文字にするために、音をAIの提供元（Gemini）へ送ります。音はPCに保存しません。1時間に文字にするのは10分ぶんまでです
- BGMなど続いている音は「下地」として覚え、それより十分大きい音だけを声とみます（BGMの上で話した声は拾い、BGMだけは拾いません）
- 文字にするとき、ルームの人の名前・AIの呼ばれ方・「聞き取りのヒント」（よく出る名前・言葉）と直近の会話を渡し、
  聞き間違いらしいところをAIが会話の流れから直します（直す前の文も判断のログに出ます）。聞き取りが不確かなときは、AIは推測で進めず聞き返します
- 誰かが話している間は、AIは喋り始めません（20秒より長く続く音はBGMなどとみます）
- AIがルームへ喋っている途中に、ほかの人が話し始めたら、AIは喋るのをやめて話を譲ります。
  相手が話し終えたら、言いかけたことが話の流れに合えば「さっきの続きだけど」などと続けます（3分で忘れます）
- AIは自分の声（読み上げタブの声のキャラ名・スタイル）を知っていて、聞こえた自分の声は「ほかの人の声」として扱いません
- 笑い声（あはは・www・（笑）・草・くさ・草生える・わろた など）や相づち（うんうん・へー など）では、AIは喋るのをやめません。
  笑い声だけには返事をしません
- このアプリの読み上げを聞き返したもの（直前のチャットとほぼ同じ文）は使いません

### 🧠 記憶（AIタブ。どれも最初はOFF）

- **会話を覚える**: GRAVITYのチャットの会話から、あとで役立つこと（人の好きな話題・この場の雰囲気・AIが言ったことや約束）をAIに選ばせて覚えます。
  次の会話から、その人と話すときに思い出して使います。GRAVITYのアカウントごとに分けて覚えます（AIタブの手入力は覚えません）
- **人の印象を推定する**: 話し方や好みの印象を「推定」として覚えます。事実として扱わず、本人に向かって言いません
- **関係の値を持つ**: AIとその人との「なじみ」と「やりとりの温かさ」を持ちます。値は口に出さず、接し方にだけ使います
- ⚠️ ルームの他の人のことも覚えるので、ONにするとき確認します。健康・信条・性的指向・犯罪歴・住所・本名などの繊細な事柄は覚えません。
  覚えたことはこのPCの中（agent_data.db）だけにあり、一覧で見て1件ずつ・全部消せます。使わない記憶は30〜180日で消えます
- **📒 会話をファイルに残す**: GRAVITYのチャットの会話を、アプリのフォルダの「AIの記憶」に、メモ帳で読めるファイルで残します。
  GRAVITYのアカウントごとのフォルダに、その日の全文（`会話の記録/日付.md`）と、話した相手ごとのファイル
  （`相手/名前.md`。AIがまとめた「覚えていること」と、その人の発言・AIの返事）ができます。「📂 フォルダを開く」で開けます
  - **AIも読みます**: 話しかけてきた人のファイルの「## メモ（自分で書く）」に書いたこと（例: 常連さん・この話題は避ける）を、
    AIは確かなこととして使います。前にその人と話したこと（数行）も読むので、「この前の話の続き」ができます
  - ⚠️ ルームの他の人の名前と発言がそのまま入るので、ONにするとき確認します。このPCの中だけで、自動では消しません（読む・消すのは自由です）
  - どのGRAVITYのアカウントでチャットしているかは、AIが送った文がチャット欄に出たときの名前・タスク機能が覚えた名前・
    「自分のアカウント名」の設定から見分けます（MuMuのアプリ複製で動かしているGRAVITYも、それぞれのアカウントとして分けます）
- 「会話を覚える」がONなら、3日以上来ていなかった人が来たときに「久しぶり」とAIに伝えます
- 「会話を覚える」がONなら、人が話した予定（「来週の金曜テスト」など）も覚えて、近づいたら・過ぎたら思い出します
  （過ぎたあとに一度話しかけたら終わり。その日から2週間で忘れます）
- 会話で使った記憶は長く残り（最長1年）、古くなった・間違いと分かった記憶は、整理のときに消します
- **📝 1日のまとめを作る**（既定OFF。「会話をファイルに残す」がONのとき）: 会話が静かなときに、前の日の会話の記録から
  「AIの記憶」の「まとめ」フォルダにまとめを作ります（AIを1日1回呼びます）。「📝 今日のまとめを作る」で、今日の分もすぐ作れます
- 覚えることの整理にもAIを使います（他の人の発言が6件たまって、10分たつか2分静かになったとき）。回数と費用の上限に数えます
- **👑 オーナーの自己分析を読む・気づいたことを書き足す**（最初はOFF）: 「📁 選ぶ」で自分の自己分析のフォルダを選ぶと、
  中のメモ（.md / .txt）をAIが「オーナーと話すときに役立つ人物像」に短くまとめ、オーナーが会話にいるときに使います
  （本名・会社名などはまとめに書かせません。ルームでは話題にしません）。「会話を覚える」もONなら、ルームでのオーナーの発言・
  ふるまいから気づいたこと（性格・人への接し方・癖・言動のパターン）を、そのフォルダの「AIが気づいたこと.md」に日付つきで書き足します。
  まとめるために、フォルダの中身をAIの提供元へ送ります

### 🪪 GRAVITYのアカウント（AIタブ）

- AIを動かすGRAVITYのアカウントごとに、**呼ばれ方・オーナーの名前・人格**を変えられます。空の欄は「⚙️ 設定」と共通の人格を使います
  - 「🎭 このアカウントの人格を編集」を押すと、下の「🎭 人格」の欄がそのアカウント用になります（「↩ 共通の人格を編集」で戻ります）
- 名前が分かる前に「本体のGRAVITY」などの仮の呼び名で覚えた記憶とファイルは、名前が分かったときに自動でそちらへ移します
- アカウントごとに分ける前に覚えた記憶は「📦 このアカウントの記憶にする」で、選んだアカウントの記憶にできます
- 記憶の一覧は、表示するアカウントで絞れます
- **自分のアカウント名**: GRAVITYでのこのアカウントの表示名。この名前の発言（MuMuで直接打った発言も）と、
  このアカウントがしたこと（いいね・参加など）のお知らせは、AI自身のこととして扱い、反応しません。名前が「..」で切れて出ても見分けます
- **1日にAIを呼ぶ上限**（既定300回）を超えると、記録だけにします
- **AIの声は読み上げツール（VOICEVOX / AivisSpeech）で作ります。** AIは文ごとに、今の声と同じキャラの
  声の様子（ノーマル・喜び など）・速さ・抑揚を選び、読み上げツールに渡します。声は読み上げタブの声・音量（人格で声を選べばその声）です
  - 「🔊 声で答える（PCのスピーカーだけ）」ならPCのスピーカーにだけ鳴ります
  - 「📢 声で答える（読み上げの出力先＝ルームへ）」なら、読み上げと同じ出力先（VB-CABLE など）からルームへ流れます（選ぶときに確認します）
- **■ 停止**: 新しい出来事を受け付けません。喋っている文は最後まで喋ります
- **🛑 緊急停止**: AIも音声（読み上げも）もすぐ止め、「↩ 再開」を押すまで何もしません
- **⏹ 音声を止める**: 読み上げタブの「⏹ 止める」と同じです（AIの声も読み上げも止めます）
- **Geminiのモデル**: 既定は「Gemini 3.5 Flash-Lite」（安い・速い）。変えたら次の「▶ 開始」から使います
- **費用の上限**: 既定は 1日 $1・1か月 $10。費用の**見積もり**（請求額ではありません）が8割を超えたら知らせ、超えたらAIを呼ばず記録だけにします
- **🎭 人格**: AIの名前・要約・性格・話し方・しないこと・口調の例。文の作り方にだけ効きます（喋る回数や間の規則は変わりません）

⚠️ **Gemini の無料枠では、送った内容が Google の製品の改善に使われます**（有料枠では使われません。2026-10-15 時点の Google の案内）。
GRAVITYのチャットを渡すと、ルームの他の人の名前と発言も送ることになります。

### GRAVITYのチャットをAIに渡す（💬 のスイッチ）

- **既定はOFF**。ONにするとき、模擬以外のAIなら「他の人の名前と発言を送ってよいか」を聞きます（提供元ごとに1回。提供元を変えたら聞き直します）
- 届くのは**メインタブで監視している間**だけです。AIを「▶ 開始」していないときは何も渡しません
- **始めた時点で画面にあった行**・**チャット欄を上へ戻して出てきた昔の行**は「前からの会話」として渡します（AIはこれには反応しません）
- 同じ画面を何度読んでも、同じ行は1回だけ渡します。同じ人が同じ文をもう一度言ったら、それは新しい行です
- 手入力で送った文・キーワード自動返信の文は「自分の発言」として渡します（AIは反応しません）
- 声で答えるときは、「ルームへ」を選んだときだけルームに流れます。キーワード自動返信は今まで通り動きます
- AIタブの「🧾 判断のログ」に、渡した行（📥 [GRAVITY]）と判断が出ます。AIの文を実際にチャットへ送れたか（✉️）、
  チャット欄が隠れて読めない・また読めるようになった、もここに出ます

### 応答のしかた（🔊 声 / 💬 チャット）

AIタブの「応答のしかた」で切り替えます。既定は「🔊 声で答える（PCのスピーカーだけ）」です。

- **💬 チャットに書き込む**: AIの文を、このアカウントの発言としてルームのチャットに書き込みます（選ぶときに確認します）
  - 送るのは**メインタブの監視**です（手入力送信と同じ送信待ちに並びます）。監視していないと送れません
  - **1分に1通・1時間に20通まで**（声より厳しくしてあります）。チャット向けの短い文を作らせます
  - 送った文がチャット欄に出ても、自分の発言なのでAIもキーワード自動返信も反応しません
- **チャットに送る前に**:
  - **毎回確認する（既定）**: 下書きの窓が出ます。直してから「📨 送る」、または「🗑 捨てる」。**60秒たつと捨てます**。捨てた分は回数に数えません
  - **確認せずに送る**: 選ぶときに確認します。AIが変なことを書いても送る前には止められません
- **🛑 緊急停止**で、出ている下書きはすぐ閉じ、送信待ちに残っている**AIの文だけ**を捨てます（手入力した文は残します）

⚠️ **記録（`agent_data.db`）**: AIを初めて使ったときに、アプリのフォルダ（`app_data.db` の横）に作ります。
出来事・判断・発言・AIを呼んだ回数を残します。**他の人の名前や発言がそのまま入る**ので、出来事は7日、
判断・発言は30日で自動で消します。リポジトリには入れず、自動更新でも上書きしません。
1日1回 `backup/agent_data_YYYYMMDD.db` にバックアップを作り（7世代）、壊れていたら最新のバックアップから戻します。

## ダイアログの自動OK

設定タブの「✅ ダイアログの自動OK」で、抽選の当選ダイアログなどを自動で閉じられます。

- 既定は**OFF**です。使うときはチェックを入れてください
- 「目印の文言」に指定した語がダイアログ内にあるときだけ、OKボタンを押します
  （既定: `当選者,選ばれました` / カンマ区切りで複数指定可）
- 押す対象は `OK` `はい` `確認` `閉じる` などの完全一致のみ
- 同じダイアログを連打しないよう、押した直後の2秒間は反応しません

⚠️ **「OKボタンを見つけたら押す」という作りにはしていません。** 購入確認・規約同意・権限許可
などにもOKボタンはあり、誤って押すと取り返しがつきません。**必ず目印が同じ画面にある場合だけ**
押します。目印を空にすると（判断できないため）何も押しません。

⚠️ 目印を `OK` のような汎用的な語にしないでください。あらゆるダイアログが対象になります。

## 返信の送信手順（アプリ内）

検知ワードを見つけたあと、次の順で送信します。

1. 画面下部の入力欄（「メッセージを送信」）をタップ
2. 返信ワードをクリップボードに載せ、**貼り付けキー(KEYCODE_PASTE)で入力欄に貼り付け**
3. 貼り付いたか画面で確認し、反映されていなければ従来どおりIMEで直接入力に切り替え
4. アプリの「送る」ボタンをタップ
5. 送るボタンが無いレイアウトの場合のみ、保険としてEnterキーを押す

日本語をIMEで1文字ずつ送るより速く、変換の途中状態が残らないため確実です。
貼り付けを受け付けない端末でも、自動で直接入力に切り替わるので送信自体は止まりません。

### 送信ボタン検出の注意点（変更する場合）

- **uiautomator2の入力補助バーにも「Send」ボタンがあります。** アプリの「送る」と間違えて
  押さないよう、`package` が `com.github.uiautomator` の要素は除外しています
- **入力欄の案内文が「メッセージを送信」で「送信」を含みます。** 部分一致だけで探すと
  送信ボタンのつもりで入力欄を押してしまうため、まず完全一致（`送る`/`送信`/`Send`など）で
  探し、見つからないときだけ部分一致にフォールバックします
- **送信できたかの判定は「入力欄が空か」ではなく「入れた文字が消えたか」で行います。**
  入力欄は空のとき案内文が文字として入っているため、空判定にすると
  送信できていても失敗扱いになります

## 保存したタイマー一覧

タイマータブで、よく使う時間に名前を付けて保存し、一覧から呼び出せます。

- 「💾 現在の時間を保存」で、入力中の時・分・秒に名前を付けて保存します
- 一覧をクリックすると上の入力欄に読み込まれ、ダブルクリックでそのまま開始します
- 「✏️ 名前変更」「🗑️ 削除」で整理できます
- 同じ名前で保存しようとすると、上書きするか確認します
- タイマーが動作中・一時停止中に別のタイマーへ切り替えるときは確認が入ります
  （クリックしただけでは切り替わらず、ダブルクリックか各ボタンで切り替えます）

保存内容は `app_data.db` の `timer_presets` テーブルに入るため、アップデートしても消えません
（更新時の差し替えは `app_data.db` を除外しているため）。

## 読み上げタブ（ずんだもんに喋ってもらう）

マイクで話せないときに、打った文をずんだもんの声で流すための機能です。

音声はPCの既定の出力先（スピーカー）に鳴ります。これは意図した仕様です。
MuMuのマイク入力へ配線する必要はないので、仮想オーディオデバイスの導入は不要です。

### 声と音量の設定

読み上げタブの「🎤 読み上げの声」で設定します。

- **キャラ** — VOICEVOXに入っている全キャラから選べます（ずんだもん以外も可）
- **スタイル** — 選んだキャラが持つスタイル（ノーマル／あまあま／ツンツン等）
- **音量** — スライダーで0〜100%
- 「🔄 キャラ一覧を取得」でVOICEVOXから最新の一覧を読み込みます
  （タイマータブの「🔄 接続確認」と同じ処理で、取得結果は両方で共有されます）
- 「🔊 試聴」で現在の設定のまま鳴らせます

**読み上げの声・音量は、アラーム音の声・音量とは別に保存されます。** アラームは気付きたいので
大きめ、読み上げは会話用に控えめ、といった使い分けができます。アラーム側の声も
タイマータブで同じく全キャラから選べます。
入力元は3つあり、すべて同じ読み上げの待ち行列に入って順番に処理されます。

1. **貼り付け欄** — LINEなどからコピーした文を貼り付けて「🔊 読み上げ」(Ctrl+Enter)
2. **クリップボード自動読み上げ** — ONの間、文字をコピーするたびに自動で読み上げます
3. **スマホから送信** — 同じWi-Fiのスマホのブラウザから文を送ると、PCのずんだもんが読み上げます

スマホの解析ページでアクセントを直して喋らせた文も、同じ待ち行列に入ります（ほかの読み上げと重なりません）。

### 読み上げを止める

「読み上げ待ち」の横の **「⏹ 止める」** で、今の読み上げを途中で止め、待っている分も取り消します。
止まるまでの遅れは0.2秒以内です。

- 止まるのは読み上げだけです。**タイマーのアラームは止まりません**（アラームは「OK」で止めます）
- アラームは「OK」を押した時点で、鳴っている途中の音も止まります（以前は最後まで鳴ってから止まっていました）
- アラームは読み上げの待ち行列に入りません。読み上げが詰まっていても時間どおりに鳴ります

### 履歴と定型文

- **履歴** — 読み上げた文は読み上げタブの「🕘 読み上げた履歴」に最大30件たまります。
  ダブルクリックでもう一度読み上げできます。**アプリを閉じると消えます**
- **定型文** — また使う文は「⭐ 定型文に保存」しておくと残ります。
  ダブルクリックで読み上げ、「✏️ 入力欄に取り込む」で編集してから使うこともできます
- 保存した定型文は**スマホ側の画面にも並び**、タップするだけで読み上げられます
- スマホの入力欄の「⭐」でも定型文を保存でき、PC側の一覧にもすぐ反映されます
- スマホの履歴もタップでもう一度読み上げられます

### スマホ画面の構成

画面を左右に分けています。

```
┌──────────────┬──────────────┐
│ 送信した内容    │ 登録したワード  │
│              │ [▶] ワード [×] │
│   送った文     │ [▶] ワード [×] │
│   ✓ 読み上げ   │ [▶] ワード [×] │
├──────────────┴──────────────┤
│ [入力欄]            [⭐] [送る] │
└─────────────────────────────┘
```

- **左** — 送信した内容。タップでもう一度読み上げ
- **右** — 登録したワード。**左の [▶] で送信**、文字部分をタップしても送信できます
- **[×]** で削除（誤操作を防ぐため確認が出ます）
- **[⭐]** で入力中の文をワードとして登録
- キーボードが出ると画面全体が縮み、**左右のリストは隠れません**（打ちながらワードを選べます）

### スマホ連携の使い方

1. 読み上げタブの「スマホからの受け取りを有効にする」をON
2. 画面に出るURL（例 `http://192.168.1.2:8765/`）をスマホのブラウザで開く
3. 画面に出ている暗証番号をスマホ側に入力する（次回以降は端末が覚えます）
4. スマホで文を打って送信すると、PC側で読み上げられます

⚠️ **暗証番号は必須です。** このサーバーは「受け取った文をPCに喋らせる」ものなので、
無防備に開くと同じネットワークにいる人が自由にPCから音を出せてしまいます。
そのため既定ではOFFで、送信には毎回暗証番号の照合を行い、
番号は「🔢 暗証番号を作り直す」でいつでも変更できます（動作中でも即座に切り替わります）。

暗証番号を**5回続けて間違えると30秒間すべての送信を受け付けません**。
6桁は同じWi-Fi内から総当たりできてしまう桁数のため、
総当たりに現実的でない時間がかかるようにしています
（この制限が無いと約3時間で破られますが、あると約70日かかります）。
定型文の取得にも同じ照合を通しているので、保存した文が第三者に見られることもありません。

⚠️ **LINEのトーク内容を直接読み取ることはできません。** LINEには個人アカウントの
受信メッセージを取得する正規の手段が無いためです（Messaging APIは公式アカウント宛専用、
LINE Notifyは2025年3月終了）。上記のコピー＆貼り付け、またはスマホからの送信をお使いください。

## VOICEVOXの同時起動

読み上げタブの「このツールの起動と同時にVOICEVOXも起動する」をONにすると、
アプリの起動時にVOICEVOXも自動で立ち上がります。

- 事前に「📂 場所を選択」で `VOICEVOX.exe` の場所を指定してください
- すでにVOICEVOXが起動している場合は二重に起動しません
- プロセスが立ち上がっただけでは音声合成できないため、エンジンが応答を返すまで
  （`/version` が通るまで、最大90秒）待ってから「起動完了」と表示します

## 取得元リポジトリの設定（GitHub連携）

設定タブの「GitHub連携」で、アップデートを取得するリポジトリを変更できます。
`auto_reply_app.py` の `GITHUB_OWNER` / `GITHUB_REPO` は**既定値**になり、
設定した場合はそちらが優先されます（**exeを作り直さずに配布元を切り替えられます**）。

- 入力欄には `owner/repo` のほか、GitHubのURLをそのまま貼り付けても構いません
  （`https://github.com/owner/repo/releases/latest` のような形でも owner/repo を取り出します）
- 「🔗 接続テスト」で、保存前に実際に問い合わせて確認できます。
  リリースが取れるかだけでなく、**zipファイルが添付されているか** まで確認します
  （zipが無いリリースは、更新の段階になって初めて失敗するため）
- 「↩️ 既定に戻す」でソースの既定値に戻ります
- 取得元を変更すると、ダウンロード済みの更新ファイルは破棄されます
  （別リポジトリのファイルを誤って適用しないため）

⚠️ 未認証でGitHub APIにアクセスするため、指定できるのは **publicリポジトリのみ** です。
privateリポジトリを指定すると、リポジトリ名が正しくても404になり更新を検知できません。

## 自動アップデート（既定でON）

設定タブの「自動アップデート」でON/OFFを切り替えられます。ONのときの動作:

- 起動時と、その後6時間ごとに新しいバージョンを確認します
  （長時間起動しっぱなしになる使い方でも新版に気付けるようにするため）
- 新しいバージョンが見つかると、**裏でダウンロードして展開するだけ** で止めておきます。
  確認ダイアログは出ないため、監視中でも作業は一切中断されません
- 準備ができるとメインタブのバージョン表示が「終了時に vX.Y.Z を適用します」に変わります
- **実際の差し替えはアプリを閉じたときに行われます。** 監視スレッドが完全に停止したことを
  確認してから差し替え、更新後の自動再起動はしません（次に自分で起動したときに新版になります）
- 準備済みファイルは `%LOCALAPPDATA%\AutoReplyTool\pending_update` に置かれます。
  ⚠️ アプリフォルダの中に置いてはいけません（差し替えのrobocopyが自分自身をコピーし続けるため）

OFFにすると、これまでどおり「新しいバージョンがあります」の確認ダイアログが出るだけになり、
ダウンロード済みの準備物はその場で破棄されます。
「🔄 アップデート確認」ボタンからの手動更新は、ON/OFFに関わらず従来どおり即時適用＋再起動です。

なお、`.py` で直接実行している開発環境では、差し替える対象のexeが無いため
自動ダウンロード・自動適用はどちらも行いません。

## 初回セットアップで確認すること

- このフォルダ（`auto_reply_app.py` がある階層）が git リポジトリのルートになっていること。
  ワークフローは `.github/workflows/release.yml` に置く必要があり、
  この場所以外だと GitHub Actions は一切動きません。
- リポジトリの Settings → Actions → General で、
  "Workflow permissions" が "Read and write permissions" になっていること
  （Release作成に書き込み権限が必要なため）
- 初めてzip方式でリリースする際は、実際にダウンロード→展開→差し替えの流れが
  問題なく動くか、一度手元で確認することをおすすめします
