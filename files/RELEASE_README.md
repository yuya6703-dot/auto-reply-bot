# リリース手順（自動ビルド＆自動リリース）

`.github/workflows/release.yml` を設定済みなら、以下の3手順だけで新バージョンを配布できます。
手元でのexeビルドやGitHub Releaseページの手作業は不要です。

## 手順

1. **コード内のバージョンを上げる**

   `auto_reply_app.py` の冒頭にある以下の行を、新しいバージョン番号に書き換える。

   ```python
   APP_VERSION = "1.1.0"
   ```

2. **変更をコミットしてpush**

   ```bash
   git add auto_reply_app.py
   git commit -m "v1.1.0: 変更内容の説明"
   git push
   ```

3. **バージョンと同じ番号でタグを作り、push**

   ```bash
   git tag v1.1.0
   git push origin v1.1.0
   ```

   ※ タグ名の数字部分（`v1.1.0` の `1.1.0`）は、手順1の `APP_VERSION` と必ず一致させてください。
   ずれるとアプリ側のアップデート判定がおかしくなります。

## 何が自動で起きるか

タグをpushすると、GitHub Actions が自動的に：

1. Windows環境でPythonと依存パッケージをセットアップ
2. PyInstallerで `自動送信ボット.spec` を使い、`dist/自動送信ボット` フォルダ一式をビルド
   （`--onedir` 方式、exe＋依存ファイル）
3. そのフォルダの中身を `auto_reply_app.zip` にまとめる
4. zipを添付した新しいGitHub Releaseを、タグ名と同じバージョンで自動作成
5. リリースノートも、前回タグからのコミット履歴をもとに自動生成

### ⚠️ exe名について（重要）

アプリの自動更新は、**今動いているexeと同じ名前のexe** をzipの中から探して差し替えます。
そのため、ビルドされるexe名が配布中のexe名（`自動送信ボット.exe`）と食い違うと、
更新が必ず「zip内に見つかりません」で失敗します。

これを防ぐため、CIは手元と同じ `自動送信ボット.spec` を使ってビルドしています。
exe名を変えたい場合は、specファイルの `name=` を書き換えてください
（`.github/workflows/release.yml` 側にexe名を直接書かないこと）。

⚠️ exe名を変更した場合、**変更後のバージョンから先** でないと自動更新は成功しません。
配布済みの旧バージョンは古い名前のexeを探し続けるためです。
名前を変える場合は、利用者に手動での入れ替えを案内してください。

進捗は、GitHubリポジトリの「Actions」タブから確認できます（数分かかります）。
完了すると「Releases」ページに新しいzipが並び、アプリ内の「🔄 アップデート確認」ボタンや
起動時の自動チェックで検知されるようになります。

## アップデート適用時の動作（アプリ内）

- 新しいzipをダウンロードし、一時フォルダに展開
- 展開したフォルダの中から新しいexeを探し、そのフォルダを新しいアプリ本体として使用
- 更新前に、現在のアプリフォルダ一式を `%USERPROFILE%\AutoReplyTool_Backups` にzipでバックアップ
- `app_data.db`（キーワード設定・各種設定）と `error_log.txt` は上書き・削除の対象外（ユーザーデータは保持されます）
- アプリを終了し、外部PowerShellスクリプト(.ps1)がファイルの差し替えを行う
  （フォルダ名に日本語が含まれるとcmdのbatでは誤動作するため、PowerShellを使っています）

## ログのコピー

メインタブのログは読み取り専用ですが、コピーできます。動作の報告や不具合の相談に使ってください。

- **「📋 ログをコピー」ボタン** — ログ全体を一発でコピー
- **右クリック** — コピー / すべて選択 / ログ全体をコピー / 表示を消去
- **Ctrl+A** で全選択（TkのTextは既定でCtrl+Aが「行頭へ移動」なので割り当て直しています）
- マウスでドラッグして一部だけ選び、右クリック→コピーも可能

⚠️ クリップボードの自動読み上げがONでも、ここでコピーした内容は読み上げられません
（自分でコピーしたものは監視対象から外しています）。

「表示を消去」で消えるのは**画面の表示だけ**です。監視ログのDB保存分は消えません。

## エミュレータ(MuMu)の検出・起動

設定タブの「📱 エミュレータ(MuMu)」で、MuMu本体と監視対象アプリの起動をツールから行えます。

- **接続先(adbのホスト/ポート)はMuMuに直接問い合わせます。** 手で設定する必要はありません
- 「🔄 一覧を取得」でMuMuにインストール済みのアプリが並ぶので、監視したいアプリを選びます
  （パッケージ名を手入力する必要はありません。自動化補助のATXは一覧から除外されます）
- 「監視を開始するとき、MuMuと上のアプリを自動で起動する」をONにすると、
  MuMuが落ちていても起動→Android起動完了を待つ→対象アプリを開く、まで自動で行います
- 「▶ 今すぐ起動」「🔌 接続を確認」でその場で試せます

⚠️ **adbのポートを決め打ちしてはいけません。** MuMu Player 12はインスタンスごとにポートが変わり、
ホストも `127.0.0.1` とは限りません（実測環境では `192.168.1.7:5555` で、
以前試していた `127.0.0.1:7555` / `16384` はどちらも接続拒否でした）。
`MuMuManager.exe info -v <番号>` が正確な値を返すので、必ずそちらを使ってください。

⚠️ **インスタンス番号も決め打ちしてはいけません。** MuMuをアップデートすると番号が変わります
（実測: 5.30 では `0`、6.4.7 では `1`）。しかも端末が1台しか無くても `is_main` が `false` に
なるため、「0番」も「メイン」も当てになりません。`info -v all` の一覧から拾ってください。
本ツールは番号を自動検出し、保存済みの番号が実在しない場合は自動で読み替えます
（優先順: 起動中 > メイン指定 > 一番小さい番号）。

MuMuManagerがエラーを返した場合（`{"errcode": -200, "errmsg": "player index not found"}` など）は、
その `errmsg` をログに出します。「MuMuが起動しない」ときはまずログを確認してください。

MuMuが入っていない環境（BlueStacks / LDPlayer など）では、この機能は自動的に無効になり、
従来どおりadbの探索で接続します。

## ダイアログの自動OK

設定タブの「✅ ダイアログの自動OK」で、抽選の当選ダイアログなどを自動で閉じられます。

- 既定は**OFF**です。使うときはチェックを入れてください
- 「目印の文言」に指定した語がダイアログ内にあるときだけ、OKボタンを押します
  （既定: `当選者,選ばれました` / カンマ区切りで複数指定可）
- 押す対象は `OK` `はい` `確認` `閉じる` などの完全一致のみ
- 同じダイアログを連打しないよう、押した直後の2秒間は反応しません

⚠️ **「OKボタンを見つけたら押す」という作りにはしていません。** 購入確認・規約同意・権限許可
などにもOKボタンはあり、誤って押すと取り返しがつきません。**必ず目印が同じ画面にある場合だけ**
押します。目印を空にすると（判断できないため）何も押しません。

⚠️ 目印を `OK` のような汎用的な語にしないでください。あらゆるダイアログが対象になります。

## 返信の送信手順（アプリ内）

検知ワードを見つけたあと、次の順で送信します。

1. 画面下部の入力欄（「メッセージを送信」）をタップ
2. 返信ワードをクリップボードに載せ、**貼り付けキー(KEYCODE_PASTE)で入力欄に貼り付け**
3. 貼り付いたか画面で確認し、反映されていなければ従来どおりIMEで直接入力に切り替え
4. アプリの「送る」ボタンをタップ
5. 送るボタンが無いレイアウトの場合のみ、保険としてEnterキーを押す

日本語をIMEで1文字ずつ送るより速く、変換の途中状態が残らないため確実です。
貼り付けを受け付けない端末でも、自動で直接入力に切り替わるので送信自体は止まりません。

### 送信ボタン検出の注意点（変更する場合）

- **uiautomator2の入力補助バーにも「Send」ボタンがあります。** アプリの「送る」と間違えて
  押さないよう、`package` が `com.github.uiautomator` の要素は除外しています
- **入力欄の案内文が「メッセージを送信」で「送信」を含みます。** 部分一致だけで探すと
  送信ボタンのつもりで入力欄を押してしまうため、まず完全一致（`送る`/`送信`/`Send`など）で
  探し、見つからないときだけ部分一致にフォールバックします
- **送信できたかの判定は「入力欄が空か」ではなく「入れた文字が消えたか」で行います。**
  入力欄は空のとき案内文が文字として入っているため、空判定にすると
  送信できていても失敗扱いになります

## 保存したタイマー一覧

タイマータブで、よく使う時間に名前を付けて保存し、一覧から呼び出せます。

- 「💾 現在の時間を保存」で、入力中の時・分・秒に名前を付けて保存します
- 一覧をクリックすると上の入力欄に読み込まれ、ダブルクリックでそのまま開始します
- 「✏️ 名前変更」「🗑️ 削除」で整理できます
- 同じ名前で保存しようとすると、上書きするか確認します
- タイマーが動作中・一時停止中に別のタイマーへ切り替えるときは確認が入ります
  （クリックしただけでは切り替わらず、ダブルクリックか各ボタンで切り替えます）

保存内容は `app_data.db` の `timer_presets` テーブルに入るため、アップデートしても消えません
（更新時の差し替えは `app_data.db` を除外しているため）。

## 読み上げタブ（ずんだもんに喋ってもらう）

マイクで話せないときに、打った文をずんだもんの声で流すための機能です。

音声はPCの既定の出力先（スピーカー）に鳴ります。これは意図した仕様です。
MuMuのマイク入力へ配線する必要はないので、仮想オーディオデバイスの導入は不要です。

### 声と音量の設定

読み上げタブの「🎤 読み上げの声」で設定します。

- **キャラ** — VOICEVOXに入っている全キャラから選べます（ずんだもん以外も可）
- **スタイル** — 選んだキャラが持つスタイル（ノーマル／あまあま／ツンツン等）
- **音量** — スライダーで0〜100%
- 「🔄 キャラ一覧を取得」でVOICEVOXから最新の一覧を読み込みます
  （タイマータブの「🔄 接続確認」と同じ処理で、取得結果は両方で共有されます）
- 「🔊 試聴」で現在の設定のまま鳴らせます

**読み上げの声・音量は、アラーム音の声・音量とは別に保存されます。** アラームは気付きたいので
大きめ、読み上げは会話用に控えめ、といった使い分けができます。アラーム側の声も
タイマータブで同じく全キャラから選べます。
入力元は3つあり、すべて同じ読み上げの待ち行列に入って順番に処理されます。

1. **貼り付け欄** — LINEなどからコピーした文を貼り付けて「🔊 読み上げ」(Ctrl+Enter)
2. **クリップボード自動読み上げ** — ONの間、文字をコピーするたびに自動で読み上げます
3. **スマホから送信** — 同じWi-Fiのスマホのブラウザから文を送ると、PCのずんだもんが読み上げます

### 履歴と定型文

- **履歴** — 読み上げた文は読み上げタブの「🕘 読み上げた履歴」に最大30件たまります。
  ダブルクリックでもう一度読み上げできます。**アプリを閉じると消えます**
- **定型文** — また使う文は「⭐ 定型文に保存」しておくと残ります。
  ダブルクリックで読み上げ、「✏️ 入力欄に取り込む」で編集してから使うこともできます
- 保存した定型文は**スマホ側の画面にも並び**、タップするだけで読み上げられます
- スマホの入力欄の「⭐」でも定型文を保存でき、PC側の一覧にもすぐ反映されます
- スマホの履歴もタップでもう一度読み上げられます

### スマホ画面の構成

画面を左右に分けています。

```
┌──────────────┬──────────────┐
│ 送信した内容    │ 登録したワード  │
│              │ [▶] ワード [×] │
│   送った文     │ [▶] ワード [×] │
│   ✓ 読み上げ   │ [▶] ワード [×] │
├──────────────┴──────────────┤
│ [入力欄]            [⭐] [送る] │
└─────────────────────────────┘
```

- **左** — 送信した内容。タップでもう一度読み上げ
- **右** — 登録したワード。**左の [▶] で送信**、文字部分をタップしても送信できます
- **[×]** で削除（誤操作を防ぐため確認が出ます）
- **[⭐]** で入力中の文をワードとして登録
- キーボードが出ると画面全体が縮み、**左右のリストは隠れません**（打ちながらワードを選べます）

### スマホ連携の使い方

1. 読み上げタブの「スマホからの受け取りを有効にする」をON
2. 画面に出るURL（例 `http://192.168.1.2:8765/`）をスマホのブラウザで開く
3. 画面に出ている暗証番号をスマホ側に入力する（次回以降は端末が覚えます）
4. スマホで文を打って送信すると、PC側で読み上げられます

⚠️ **暗証番号は必須です。** このサーバーは「受け取った文をPCに喋らせる」ものなので、
無防備に開くと同じネットワークにいる人が自由にPCから音を出せてしまいます。
そのため既定ではOFFで、送信には毎回暗証番号の照合を行い、
番号は「🔢 暗証番号を作り直す」でいつでも変更できます（動作中でも即座に切り替わります）。

暗証番号を**5回続けて間違えると30秒間すべての送信を受け付けません**。
6桁は同じWi-Fi内から総当たりできてしまう桁数のため、
総当たりに現実的でない時間がかかるようにしています
（この制限が無いと約3時間で破られますが、あると約70日かかります）。
定型文の取得にも同じ照合を通しているので、保存した文が第三者に見られることもありません。

⚠️ **LINEのトーク内容を直接読み取ることはできません。** LINEには個人アカウントの
受信メッセージを取得する正規の手段が無いためです（Messaging APIは公式アカウント宛専用、
LINE Notifyは2025年3月終了）。上記のコピー＆貼り付け、またはスマホからの送信をお使いください。

## VOICEVOXの同時起動

読み上げタブの「このツールの起動と同時にVOICEVOXも起動する」をONにすると、
アプリの起動時にVOICEVOXも自動で立ち上がります。

- 事前に「📂 場所を選択」で `VOICEVOX.exe` の場所を指定してください
- すでにVOICEVOXが起動している場合は二重に起動しません
- プロセスが立ち上がっただけでは音声合成できないため、エンジンが応答を返すまで
  （`/version` が通るまで、最大90秒）待ってから「起動完了」と表示します

## 取得元リポジトリの設定（GitHub連携）

設定タブの「GitHub連携」で、アップデートを取得するリポジトリを変更できます。
`auto_reply_app.py` の `GITHUB_OWNER` / `GITHUB_REPO` は**既定値**になり、
設定した場合はそちらが優先されます（**exeを作り直さずに配布元を切り替えられます**）。

- 入力欄には `owner/repo` のほか、GitHubのURLをそのまま貼り付けても構いません
  （`https://github.com/owner/repo/releases/latest` のような形でも owner/repo を取り出します）
- 「🔗 接続テスト」で、保存前に実際に問い合わせて確認できます。
  リリースが取れるかだけでなく、**zipファイルが添付されているか** まで確認します
  （zipが無いリリースは、更新の段階になって初めて失敗するため）
- 「↩️ 既定に戻す」でソースの既定値に戻ります
- 取得元を変更すると、ダウンロード済みの更新ファイルは破棄されます
  （別リポジトリのファイルを誤って適用しないため）

⚠️ 未認証でGitHub APIにアクセスするため、指定できるのは **publicリポジトリのみ** です。
privateリポジトリを指定すると、リポジトリ名が正しくても404になり更新を検知できません。

## 自動アップデート（既定でON）

設定タブの「自動アップデート」でON/OFFを切り替えられます。ONのときの動作:

- 起動時と、その後6時間ごとに新しいバージョンを確認します
  （長時間起動しっぱなしになる使い方でも新版に気付けるようにするため）
- 新しいバージョンが見つかると、**裏でダウンロードして展開するだけ** で止めておきます。
  確認ダイアログは出ないため、監視中でも作業は一切中断されません
- 準備ができるとメインタブのバージョン表示が「終了時に vX.Y.Z を適用します」に変わります
- **実際の差し替えはアプリを閉じたときに行われます。** 監視スレッドが完全に停止したことを
  確認してから差し替え、更新後の自動再起動はしません（次に自分で起動したときに新版になります）
- 準備済みファイルは `%LOCALAPPDATA%\AutoReplyTool\pending_update` に置かれます。
  ⚠️ アプリフォルダの中に置いてはいけません（差し替えのrobocopyが自分自身をコピーし続けるため）

OFFにすると、これまでどおり「新しいバージョンがあります」の確認ダイアログが出るだけになり、
ダウンロード済みの準備物はその場で破棄されます。
「🔄 アップデート確認」ボタンからの手動更新は、ON/OFFに関わらず従来どおり即時適用＋再起動です。

なお、`.py` で直接実行している開発環境では、差し替える対象のexeが無いため
自動ダウンロード・自動適用はどちらも行いません。

## 初回セットアップで確認すること

- このフォルダ（`auto_reply_app.py` がある階層）が git リポジトリのルートになっていること。
  ワークフローは `.github/workflows/release.yml` に置く必要があり、
  この場所以外だと GitHub Actions は一切動きません。
- リポジトリの Settings → Actions → General で、
  "Workflow permissions" が "Read and write permissions" になっていること
  （Release作成に書き込み権限が必要なため）
- 初めてzip方式でリリースする際は、実際にダウンロード→展開→差し替えの流れが
  問題なく動くか、一度手元で確認することをおすすめします
